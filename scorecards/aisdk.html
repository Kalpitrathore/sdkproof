The gap v7 opened

Four types the model still reaches for

Every failure is the same shape: the model names a type that v7 removed. None of the four carried an @deprecated tag in v6, so nothing in the training data ever said to stop using them — real code, verified by the TypeScript compiler against the installed ai v7.0.30.

✗Typing an extracted onFinish handlerTS2724
Opus 5 wrote (v6)
import type {
  StreamTextOnFinishCallback
} from "ai"

export const handleFinish:
  StreamTextOnFinishCallback<never> =
  async ({ text, usage }) => {
    log(text, usage)
  }
v7 has no replacement
// StreamTextOnFinishCallback: gone.
// StreamTextOnAbortCallback,
// ...OnChunkCallback,
// ...OnErrorCallback all survive.

// tsc's suggestion:
//   StreamObjectOnFinishCallback
// that is streamObject's type,
// not streamText's.
The compiler sends you to the wrong function. tsc’s did-you-mean for the missing StreamTextOnFinishCallback is StreamObjectOnFinishCallback — a different function’s callback type. A developer following the suggestion lands on streamObject while writing streamText. StreamTextOnStepFinishCallback fails the same way, suggesting GenerateTextOnStepFinishCallback.
✗Naming the telemetry & tool-execution typesTS2305
Opus 5 wrote (v6)
import type {
  TelemetrySettings,
  ToolCallOptions,
} from "ai"

export const telemetry:
  TelemetrySettings = {
    isEnabled: true,
  }
v7 renamed both ✓
import type {
  TelemetryOptions,
  ToolExecutionOptions,
} from "ai"

export const telemetry:
  TelemetryOptions = {
    isEnabled: true,
  }
Two clean renames, no deprecation period. TelemetrySettings → TelemetryOptions and ToolCallOptions → ToolExecutionOptions. The old names were correct in v6 and simply stopped existing in v7 — which is exactly the shape that produces drift. A name deprecated for a year or two gets absorbed long before it is deleted; a name removed without warning does not.

Read the two scores together

Readiness tracks the drift window

The score isn't about how good the model is — it's about how recently your SDK changed. This library has now shown the full cycle. The mid-2025 tool rename was a gap Opus 4.8 fell into: 90/100. Opus 5, trained later, had absorbed it: 100/100. Then v7 shipped in June 2026 and removed four exported types, and the same model scores 71/100.

Nothing about the model got worse. The gap closed, then a new major opened a new one — on one library, measured across a year. That's the cycle the whole scoreboard is built on, and it's why a single number is worth less than the direction it's moving.

What decides the size of the gap is the deprecation runway. An API deprecated for a year or two is absorbed long before it's deleted; the model has read a thousand migration guides. An API that's correct in one major and gone in the next has no such trail. All four of these were removed with no @deprecated tag — which is why they're still being written.

No opinions — just the compiler

How this was measured

14 realistic AI SDK tasks → generated by claude-opus-5 → each solution written into a project with the real installed ai v7.0.30 (+ @ai-sdk/openai, zod) and type-checked with tsc --noEmit.
A task passes only if it compiles clean. The prompts name the functions but never the type or option names — so this measures what the model reaches for, not what it's told. Failures are the compiler's own diagnostics. Reproducible: pinned package versions, pinned model.
