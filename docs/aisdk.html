Readiness tracks the drift window

The score isn't about how good the model is — it's about how recently your SDK changed. The AI SDK's big renames landed in mid-2025. The previous model (Opus 4.8) had absorbed most of them but still missed the tool API: 90/100. Opus 5, trained more recently, closed it: 100/100. Prisma 7 shipped its breaking changes far more recently, and even Opus 5 hasn't fully caught up: 87/100.

That's the whole point. Right after a major, the gap is wide; as models retrain, it narrows — you just watched it narrow across a single model release. It re-opens on your next major, so it's a moving number worth watching, which is exactly what SDKProof tracks.

No opinions — just the compiler

How this was measured

10 realistic AI SDK tasks → generated by claude-opus-5 → each solution written into a project with the real installed ai v7.0.30 (+ @ai-sdk/openai, zod) and type-checked with tsc --noEmit.
A task passes only if it compiles clean. The prompts name the functions but never the option names — so this measures what the model reaches for, not what it's told. Failures are the compiler's own diagnostics. Reproducible: pinned package versions, pinned model.
